1. Introduction                                                      *v9filer*

v9filer is a simple file explorer plugin written in Vim9 script. It opens as
a left-side vertical split (sidebar) showing the directory contents as an
inline expandable tree, with a header showing the current root path.

The sidebar buffer is ephemeral: it is created on each open and wiped when
the sidebar window closes. Per-tab UI state (root, expanded directories,
hidden-file flag, help flag) lives in a tab-local variable instead, so
closing and reopening the sidebar in the same tab restores the previous
view. Each tab gets a uniquely numbered buffer name (`v9filer #<n>`) so two
tabs can hold a sidebar at the same directory without colliding.

Pressing <CR> on a file opens it in the last focused non-filer window,
leaving the sidebar open.

Directories are listed first (with a trailing `/`), followed by files.
Hidden files (dotfiles) are shown by default.

The header shows the current root path compactly, using `~` for the home
directory when applicable.

Entries may include a suffix indicating their type:
    `@`  symbolic link
    `*`  executable file

When the displayed directory is inside a Git repository, entries with changes
show a short status marker after the entry name and type suffix:

    `[N]`  new or untracked
    `[M]`  modified
    `[D]`  deleted
    `[!]`  merge conflict
    `[*]`  directory with changes

Directory entries show `[*]` when the directory itself or anything below it has
changes. The root directory in the header does not show a Git status marker.
Deleted files cannot appear as file entries because they no longer exist in the
filesystem, but their parent directories still show `[*]`.

Symbolic links are matched by the link path reported by Git. The link target is
not resolved for Git status, so a symlink shows the status of the link itself
and does not inherit changes from its target.

Paths used for Git status matching are mapped back to the displayed root and
normalized to absolute paths with trailing slashes removed. Symlinks are not
resolved during this normalization, so opening a repository through a symlink
keeps status markers attached to the displayed symlink path.

The filer highlights the header, directories, suffixes, hidden entries, help
text, and empty directory placeholders by default. Optional Nerd Font icons
can be added before entry names.

2. Commands                                                  *v9filer-commands*

:V9Filer [dir]                                                      *:V9Filer*
    Open the filer as a sidebar in the current tab. If [dir] is omitted, the
    current working directory is used. If a sidebar is already open in the
    current tab, it is focused and its root is updated to [dir].

:Filer [...]                                                          *:Filer*
    Alias for |:V9Filer|. Accepts the same arguments.

:V9FilerReveal                                                *:V9FilerReveal*
    Expand ancestors of the current file in the sidebar and move the cursor
    to the entry. Does nothing if no sidebar is open in the current tab or
    if the current file is outside the sidebar's root.

3. Mappings                                                  *v9filer-mappings*

Global mappings ~

Unless |g:v9filer_no_default_mappings| is set, the following mappings are
defined globally:

    <Leader>ee  Open the sidebar in the current working directory.
    <Leader>et  Open the sidebar in the directory of the current file.
    <Leader>ef  Reveal the current file in the sidebar.

Buffer-local mappings ~

The following mappings are available in the filer buffer.

Navigation ~

    <CR>    On a directory: toggle expand / collapse.
            On a file: open it in the last focused non-filer window.

    l       Change the root to the directory under the cursor.

    -       Go to the parent directory.
    <BS>    Go to the parent directory.

    Changing the root (l, -, <BS>, or opening a directory with v / s) also
    sets the tab-local working directory to the new root via |:tcd|, so
    other windows in the tab inherit the new root unless they have a
    window-local directory set with |:lcd|.

    v       Open the file under the cursor in a vertical split, splitting
            from the last focused non-filer window.
    s       Open the file under the cursor in a horizontal split, splitting
            from the last focused non-filer window.

    t       Open the entry under the cursor in a new tab. On a directory,
            the new tab's working directory is set to that directory via
            |:tcd| and a sidebar rooted at it is opened automatically. On a
            file, the file is opened in the new tab and the tab's working
            directory is set to its parent directory via |:tcd|.

File operations ~

    D       Delete the file or directory under the cursor. A confirmation
            prompt is shown before deletion. Deleting a regular directory
            recursively removes its contents, and the prompt warns about
            this. Symbolic links are removed without following the link, so
            the link target is preserved.

    r       Rename or move the file or directory under the cursor. An
            input prompt is shown, prefilled with the current basename. The
            input may be a basename, a relative path (resolved from the
            parent directory), or an absolute path; this can be used to
            move the entry into another directory. If the target already
            exists, an overwrite confirmation is shown first.

    %       Create a new file or directory. The destination is chosen from
            the cursor line: a directory row creates inside that directory,
            a file row creates inside its parent directory, and any other
            line falls back to the current root. An input prompt is shown
            for the name. A trailing `/` creates a directory. If a regular
            file already exists at the target, an overwrite confirmation is
            shown first; if a directory already exists, the command reports
            it and does nothing.

Other ~

    .       Toggle display of hidden files (dotfiles).

    R       Refresh the directory listing.

    y       Copy the path under the cursor to the `+` and `"` registers.

    x       On a Working Files row, remove the entry from the list and close
            any window in the current tab that displays that file. On other
            rows the mapping does nothing.

    ?       Toggle the quick-help header at the top of the buffer.

    q       Close the sidebar window.

4. Working Files                                        *v9filer-working-files*

The sidebar shows a per-tab "Working Files" list above the directory tree.
Files opened inside the current tab (in any non-filer window) are appended to
the list automatically, so frequently visited files stay one keystroke away
without having to expand the tree again.

Each row shows:

    icon | name | type suffix (`@` / `*`) | git status | parent path

The parent path locates the file's directory so that two files sharing a
basename remain distinguishable. v9filer picks whichever form is shorter:

    - the parent directory relative to the sidebar root (using `../` when the
      file is outside the root)
    - the absolute parent directory (with `~` substituted for `$HOME` when
      applicable)

Files at the sidebar root show no parent path. The git status marker uses the
same `[N]` / `[M]` / `[D]` / `[!]` labels as the tree.

The list survives root changes; entries simply re-render their parent path
against the new root. Files that no longer exist on disk are hidden from the
list automatically.

Press `x` on a Working Files row to remove the entry from the list. Any window
in the current tab displaying that file is closed at the same time. Other
mappings (`<CR>`, `v`, `s`, `t`, `y`) work on Working Files rows just like on
tree rows.

5. Configuration                                              *v9filer-config*

*g:v9filer_show_hidden*
    When set to |true|, hidden files (dotfiles) are shown by default.
    Default: true >
        let g:v9filer_show_hidden = false
<

*g:v9filer_width*
    Fixed width (in columns) of the sidebar window.
    Default: 30 >
        let g:v9filer_width = 40
<

*g:v9filer_auto_reveal*
    When set to |true|, the sidebar automatically reveals the current
    file when switching buffers.
    Default: false >
        let g:v9filer_auto_reveal = true
<

*g:v9filer_use_colors*
    When set to |false|, v9filer does not apply its buffer-local display
    highlights.
    Default: true >
        let g:v9filer_use_colors = false
<

*g:v9filer_nerd_font_icons*
    When set to |true|, Nerd Font icons are displayed before entry names.
    A Nerd Font compatible font is required. Icons are chosen from built-in
    filename pattern rules, plus any rules configured by
    |g:v9filer_nerd_font_icon_rules|. When no rule matches, v9filer falls
    back to a default icon for the entry kind: directory, executable file, or
    regular file.

    When set to |false|, Nerd Font icons are not displayed, even if custom
    rules are configured.

    Default: false >
        let g:v9filer_nerd_font_icons = true
<

*g:v9filer_nerd_font_icon_rules*
    Defines custom Nerd Font icon rules. This setting does not enable icon
    display by itself; use |g:v9filer_nerd_font_icons| for that.

    Custom rules are checked from top to bottom, and the first matching rule
    is used. If no custom rule matches, v9filer checks built-in filename
    pattern rules. If no rule matches, v9filer falls back to the
    default icon for the entry kind. Rule conditions are combined with AND.

    Supported condition keys are `name_pattern`, `is_dir`, and
    `is_executable`. The `name_pattern` condition is a Vim regular expression
    matched case-sensitively against the entry name, not the full path. Use a
    `color` value to change colors for specific name patterns.

    Default: [] >
        let g:v9filer_nerd_font_icons = true
        let g:v9filer_nerd_font_icon_rules = [
              \ {
              \   'text': ' ',
              \   'color': '#6D8086',
              \   'when': {
              \     'name_pattern': '\.conf$',
              \     'is_dir': false,
              \   },
              \ },
              \ {
              \   'text': ' ',
              \   'color': '#F14E32',
              \   'when': {
              \     'name_pattern': '\v^(\.gitignore|\.gitattributes)$',
              \   },
              \ },
              \ ]
<

Highlight groups ~

The default highlight links and colors are:

    V9FilerBreadcrumb      -> Title
    V9FilerDirectory       -> Directory
    V9FilerFile            -> Normal
    V9FilerMarker          -> Special
    V9FilerGitModified     cterm=bold gui=bold ctermfg=179 guifg=#C89B5A
    V9FilerGitNew          cterm=bold gui=bold ctermfg=108 guifg=#7FAF7F
    V9FilerGitDeleted      cterm=bold gui=bold ctermfg=203 guifg=#D75F5F
    V9FilerGitConflict     cterm=bold gui=bold ctermfg=197 guifg=#FF005F
    V9FilerIconDirectory   -> Directory
    V9FilerIconFile        -> Normal
    V9FilerIconExecutable  -> Statement
    V9FilerSymlink         -> Special
    V9FilerExecutable      -> Statement
    V9FilerHidden          -> Comment
    V9FilerHelp            -> Comment
    V9FilerEmpty           -> Comment
    V9FilerWorkingFilesHeader -> Title
    V9FilerWorkingFilesPath   -> Comment

When |g:v9filer_nerd_font_icons| is enabled, icons are highlighted by entry
kind by default. Built-in rules, fallback icons, and
|g:v9filer_nerd_font_icon_rules| may set `color` directly. v9filer creates
internal highlight groups per color value, so icon glyph selection and the
public highlight interface do not grow for every filename or extension.

*g:v9filer_no_default_mappings*
    When set to |true|, the default global mappings are not defined, allowing
    you to set your own. >
        let g:v9filer_no_default_mappings = true
        nnoremap <silent> <F3> <Cmd>V9Filer<CR>
<

6. Breaking Changes                                          *v9filer-breaking*

Compared to earlier releases:

- `:V9Filer` no longer toggles the sidebar closed when re-run. Re-running
  `:V9Filer` always leaves the sidebar open: with no argument or the same
  [dir] the sidebar is focused; with a different [dir] the root is updated.
  Use `q` to close the sidebar.

- The `C` mapping (`LcdRoot`) has been removed. Changing the root now
  updates the tab-local working directory automatically via |:tcd|, which
  also propagates to the editing window in the same tab.

- Embedded mode has been removed. `:V9Filer` now always opens the sidebar.
  The `-toggle` argument is no longer recognised; pass the directory
  directly.

- `<Leader>eE` and `<Leader>eT` (embedded-mode mappings) have been removed.

- Buffer names changed back from `v9filer-toggle://<path>` (and the dropped
  `v9filer-embedded://<path>`) to `v9filer://<path>`, and then to the current
  abstract form `v9filer #<n>` (where `<n>` is a tab-stable identifier). The
  current root is shown in the breadcrumb header inside the buffer.

- The sidebar buffer became ephemeral (`bufhidden=wipe`). Sidebar UI state
  moved to per-tab variables (`t:v9filer_root`, `t:v9filer_expanded`,
  `t:v9filer_show_hidden`, `t:v9filer_help`) so it survives buffer wipe
  within the same tab. External scripts that detect a filer buffer should
  test `b:v9filer_state` rather than match the buffer name.

- The internal tab-local variable changed from `t:v9filer_toggle_buf` to
  `t:v9filer_buf`.

- `g:v9filer_icons` and `g:v9filer_icon_map` were removed. Use
  `g:v9filer_nerd_font_icons` to enable the built-in Nerd Font icon set.

- `g:v9filer_nerd_font_icons` no longer accepts custom rule lists. Use
  `g:v9filer_nerd_font_icon_rules` for rule configuration.

- `g:v9filer_nerd_font_icon_colors` was removed. Use custom rules in
  `g:v9filer_nerd_font_icon_rules` with a `color` value for name-pattern
  specific icon colors.

- `name_lc` was removed from Nerd Font icon rule conditions. Use
  `name_pattern` and list each filename variant explicitly when different
  cases should match.

- `is_symlink` was removed from Nerd Font icon rule conditions. Use
  `name_pattern` when symlink entries need custom icon rules.

- `name`, `extension`, `path`, `path_glob`, and `path_pattern` were removed
  from Nerd Font icon rule conditions. Use `name_pattern` to match entry
  names with a Vim regular expression.

- Git status markers changed from `[+]`, `[~]`, and `[*]` to color-coded
  `[N]`, `[M]`, `[D]`, `[!]`, and `[*]` markers. The highlight groups were also
  split into `V9FilerGitNew`, `V9FilerGitModified`,
  `V9FilerGitDeleted`, `V9FilerGitConflict`, and
  `V9FilerGitDirectoryChanged`.
